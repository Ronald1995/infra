### What this PR does / why we need it?

Consolidate RFC #18920 phases 1a and 1b in this PR, superseding #20866.
NPUWorker inherits from GPUWorker and calls the actual parent constructor
through super().__init__(). Existing NPU execution and lifecycle behavior is
preserved while newly visible upstream APIs remain disabled until validated.

- Keep all 54 existing non-constructor NPUWorker methods, signatures and
  decorators unchanged against baseline 28065346d433f9d23157c77c2b5b79c959a61871.
  This includes execute_model, sample_tokens, update_config, reload_weights,
  load_model, execute_dummy_batch, sleep/wake and shutdown.
- Implement only the two hooks required by parent construction:
  _make_elastic_ep_executor and _validate_profiler_config. The unsupported
  executor owns no resources or thread pool and avoids CUDA elastic-EP imports.
- Explicitly override all 29 other newly visible GPUWorker methods/properties
  with NotImplementedError, including private helpers and defaults returning
  None, False or empty results. Preserve the property descriptors.
- Reject missing parent hooks and GPU fault tolerance before parent construction.
- Record the immutable interface inventory and add guards against new upstream
  interfaces escaping the boundary on dependency upgrades.
- Retain NPU/HCCL and current V2, encoder-only, 310P and Xlite initialization.
  The Phase 0.5 alignment and old #20866 shutdown migration are excluded.

A later focused PR may remove a stub only after validating the NPU runner,
device and supported-version contract. Phase 0 tooling and earlier migration
drafts remain independent work; no Ascend successor stack is required.

### Required vLLM API

The dependency remains vLLM #65565, based on verified 24420b7a. The review pin
is e9f031bed0d150e2bef4b1eaa29aa50061e89203. Before rollout, use a merged upstream
commit containing the constructor hooks and qualify/backport them for the
matched v0.33.0 release. Missing hooks fail clearly; parent construction is
never bypassed.

### Does this PR introduce _any_ user-facing change?

Yes. Construction adopts parent-owned state and the platform-hook dependency.
APIs newly exposed by GPUWorker inheritance explicitly raise NotImplementedError
until validated. Existing NPU Worker methods retain their implementation.
Release note: release_notes/fragments/20865.yaml.

### How was this patch tested?

- python tests/ut/worker/test_worker_rfc_contract.py -v: **6 passed**.
  Covers all 29 method/property rejection paths without initialized Worker
  state, exact stub inventory, actual parent-call structure, both missing-hook
  cases, enabled fault tolerance, profiler settings and repeated executor shutdown.
- AST comparison against Ascend baseline 28065346d: **all 54 existing
  non-constructor methods and decorators unchanged**. Existing methods do not
  directly reference the newly blocked self helpers.
- Source-declaration guard against actual pinned parent source: passed.
  In-memory mutations adding a parent API or removing a quarantine stub both
  fail the guard. These are source checks, not accelerator/runtime evidence.
- Added tests/ut/worker/test_worker_inheritance.py for the actual installed
  Worker interface surface and real GPUWorker construction with WorkerBase
  configuration setup replaced by a test double.
- Ruff check/format, Markdown lint, release-note parsing, git diff --check,
  and direct long-function/symbolic-meta checks passed.
- Required bash format.sh ci was attempted. Ruff, spelling, typos, clang-format,
  actionlint, PNG, filename, package-init, forbidden-import and boolean-context
  checks passed. Markdown formatter changes were reviewed and Markdown lint
  passed on rerun. Full suite remains incomplete on Windows: /bin/bash hooks
  and shellcheck are unavailable, and two hooks cannot resolve python3
  (their scripts passed when run directly with Python).
- Runtime pytest was attempted through the normal conftest and failed loading
  local PyTorch c10.dll with WinError 1114. Actual installed-Worker integration,
  startup, serving, supported-version and NPU validation remain pending.
  No remote NPU validation was run. Keep this PR draft.
