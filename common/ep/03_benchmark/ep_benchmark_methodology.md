# EP Benchmark 方法

同组对比使用相同的硬件与网络拓扑、张量形状、数据类型和路由输入。每条结果记录测试层次、计时边界、对应的算子版本与依赖版本。

## 测试层次

| 层次 | 计时范围 | 主要指标 |
|---|---|---|
| L1 纯通信 | 单独的集合通信或 Dispatch / Combine | 延迟、收发字节、有效带宽 |
| L2 单段通算融合 | 通信与专家计算的一段融合，配独立计算基线 | 段耗时、计算量、通算重叠 |
| L3 完整专家子层 | 已给定路由的专家子层，区分前向、反向和合计 | 延迟、tokens/s、峰值显存 |
| L4 完整 MoE 层 | Router、Top-K、路由处理、专家子层及按配置启用的 Planner | 端到端延迟、吞吐、显存 |

每个后端通过能力声明标注真实入口。不支持的测试层次记录为 `unsupported`，融合收益与同口径基线比较。

## 输入与正确性

复用同一组 Routing Trace 和固定随机种子，记录 hidden states、专家 ID、路由权重、专家参数和输出梯度的生成方法。先校验输出与可用梯度，再进入性能采样。误差阈值按 dtype 和比较对象记录。

## 采样与 Profiling

- 分别记录预热轮数、采样轮数、同步点与计时工具。多 rank 测点先按轮取最慢 rank，再汇总分位数。
- 吞吐以有效源 token 数为分子。带宽注明所计字节范围和方向。
- 分开执行性能计时和 Profiling，记录采集窗口、设备时间线和峰值显存统计边界。
